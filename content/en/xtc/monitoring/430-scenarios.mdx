:::

## Setting up monitoring scenarios

All monitoring scenarios rely on [XLT test cases](/xlt/manual/test-development/) that run continuously. Organize these tests into a test suite located in the repository configured under [project configuration](/xtc/basics/project-configuration/#repository).

XLT tests are Java classes containing JUnit tests. XTC compiles these classes to execute the contained test scenarios.

## Adding a new scenario

To add a monitoring scenario, click the `+` button at the top of the scenarios list. Provide a unique **Name**, an optional **Description**, and the fully qualified **Java Class** in your repository that contains the JUnit test case.

![Creating a new monitoring scenario.](/images/xtc/monitoring_newScenario.png)
*Creating a new monitoring scenario.*  

The new scenario appears in the list. It is disabled by default and applies the [scenario default settings](/xtc/monitoring/monitoring-configuration/#scenario-defaults). Adjust these settings as needed by [editing the scenario](#managing-existing-scenarios).

:::note
New scenarios are disabled by default to give you time to finish customizing the scenario settings. Remember to enable the scenario when ready.
:::

## Managing existing scenarios

Use the _Scenarios_ table to manage scenarios. From the scenario context menu, you can edit settings, toggle scenarios or notifications, pause or resume execution, and delete scenarios.

![Overview of all existing scenarios in the project.](/images/xtc/monitoring_scenarios_overview.png)
*Overview of all existing scenarios in the project.*

### Disabling versus pausing

To stop running a scenario, select **Disable** from its context menu. Alternatively, **pause** it for a specified duration to disable it temporarily. XTC automatically resumes execution once the pause period elapses, allowing you to investigate issues without alert noise.

To pause a scenario, open the context menu, and select _Pause_. Enter the date and time until which the pause remains active. You can also pause a scenario directly from the [_Dashboard_](/xtc/monitoring/dashboard/). To resume execution before the time expires, select _Continue_ from the context menu.

## Scenario details

Click a scenario name to open its detail view. From this view, adjust [scenario settings](#scenario-settings), configure [quality sensors](#quality-sensors), and update [notification settings](#notifications). When not overridden, the scenario uses the [scenario defaults](/xtc/monitoring/monitoring-configuration/#scenario-defaults).

### Scenario settings

:::info[Role Required]
To edit scenario settings, your account must at least have the role of a [test manager](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

On the _Settings_ tab, configure how your scenario runs.

Select _Use Default_ in any section to revert to the project defaults. A dialog prompts for confirmation before discarding custom values.

![Switch between default and custom values by using the _Use Default_ checkbox.](/images/xtc/monitoring_scenario_useDefault.png)
*Switch between default and custom values by using the _Use Default_ checkbox.*

#### General

In _General_, set the scenario name and description, and specify the Java class containing the scenario.

#### Execution

In _Execution_, configure scenario execution parameters:

* **Interval**: the execution frequency, between 1 second and 24 hours.
* **Runtime limit**: the execution threshold, after which XTC aborts the scenario.

#### Retry

In _Retry_, configure retry behavior for failing runs:

* **Active**: toggle retry on or off.
* **Interval**: the delay before retrying the scenario.
* **Count**: the number of retries permitted before marking the scenario as failed.

#### Locations

In _Locations_, select where to run the scenario. Available locations depend on the machines provisioned for your monitoring project. You can also show or hide locations without provisioned machines.

#### Properties

In _Properties_, add test properties for scenario execution as key-value text lines. Ensure the property syntax is valid.

#### Notifications

Under the **Settings** tab, toggle notifications for the scenario and configure a default reply-to email address.

The scenario [**quality sensors**](#quality-sensors) and their associated [**notification lists**](/xtc/monitoring/monitoring-configuration/#notification-lists) determine when alerts trigger and who receives them.

### Quality sensors

:::info[Role Required]
To change quality sensors of a scenario, your account must at least have the role of a [test manager](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

Define **success metrics** to verify during scenario execution. Metric violations mark the scenario as failed. Configure these metrics as [quality sensors](/xtc/monitoring/monitoring-configuration/#quality-sensors) in the project settings.

Assign quality sensors to a scenario as needed. Click `+` on the _Quality Sensors_ tab to choose sensors defined in the project configuration.

XTC evaluates quality sensors in the listed order. Reorder sensors by selecting _Move Up_ or _Move Down_ in the sensor context menu.

A failing sensor can stop further evaluation if you enable _Stops Evaluation_. Use this option to prevent secondary alerts if a basic step fails.
