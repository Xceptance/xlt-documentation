## Overview

:::info[Role Required]
To use this feature, your account must at least have the role of a [reviewer](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

:::info[Role Required]
To view execution logs and measurements, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

**History** provides details about recent scenario executions. Set the time range to view in the top right (up to the limit configured in _Configuration > Data Persistence > History_). The page displays a histogram showing the proportion of execution results during this timespan, followed by a table of scenario executions. The table lists the start date, server location, and execution result details. Use a scenario context menu to open [scenario details](#scenario-details) or inspect the execution log and result browser.

### Filtering

Beyond the time range, you can filter both the histogram and the scenario executions table.

In the **histogram**, toggle scenario executions with the [status](#execution-statuses) _successful_, _fail_, _error_, _fatal_, _aborted_, or _running_ using the buttons at the top left. Hover over a histogram bar to inspect the timespan and the count of executions for each selected status.

![The histogram in the history view. You can select a time range to display and which statuses to display.](/images/xtc/monitoring_history_histogram.png)
*The histogram in the history view. You can select a time range to display and which statuses to display.*

:::note
The histogram only displays entries that appear in the table. Ensure the records you want to analyze (such as successful runs) remain visible below.
:::

In the **table** below the histogram, search directly by scenario name and filter by [execution statuses](#execution-statuses), [quality sensor states](#quality-sensor-states), scenarios, or monitoring locations.

![The scenario executions table in the history view. At the top of the table you have different possibilities for filtering.](/images/xtc/monitoring_history_table.png)
*The scenario executions table in the history view. At the top of the table you have different possibilities for filtering.*

### Execution statuses

Every scenario execution has a status, which can be one of the following:

* **Success**: the scenario ran without errors, and all success metrics passed.
* **Failed**: the scenario completed, but did not meet one or more [quality criteria](/xtc/monitoring/scenarios/#quality-sensors) (such as web vital thresholds).
* **Error**: the scenario executed but terminated early due to an error, such as an assertion failure.
* **Fatal**: the system could not execute the monitoring scenario, for instance due to compilation errors in the test suite.
* **Aborted**: the monitoring run stopped before completion, for example because it exceeded the [configured runtime limit](/xtc/monitoring/scenarios/#execution).
* **Running**: the scenario execution is in progress.

### Quality sensor states

Quality sensors report one of the following states after scenario execution:

* **Passed**: all success metrics defined in the scenario quality sensors passed.
* **Failed**: one or more success metrics failed.
* **None**: no success metrics exist.
* **Unknown**: the system could not assess success metrics because the scenario is still running or experienced a fatal error.

## Scenario details

Select a scenario name to open its detail view. The view displays options and diagnostic data reflecting whether the run is in progress, succeeded, aborted, or reported errors. Click the links in the top right to inspect the execution log and result browser or download measurements.
