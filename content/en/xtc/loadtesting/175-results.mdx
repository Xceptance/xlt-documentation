## Overview

XTC automatically downloads test results at the end of a load test run. Downloaded results appear on the _Results_ tab.

:::info[Role Required]
To view test results, your account must at least have the role of a [reviewer](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

You can download results as compressed archives to your local machine, or generate a link for [public sharing](#sharing-results). XTC also enables [generating reports](#creating-a-report-from-results) from any available result set, whether final or intermediate runs.

![Results tab and results context menu](/images/xtc/loadtest_results.png)
*Results tab and results context menu*

Results contain the [raw data recorded during a test](/xlt/advanced/results/). They are primarily useful when inspecting specific runtime events not summarized in the [test report](/xlt/manual/test-evaluation/#reading-a-test-report).

### Partial result downloads

Occasionally, downloading load test results from one or more agent machines fails due to network interruptions or an overloaded agent controller. XTC retains all successfully transferred data and generates a load test report from it. When results are incomplete, dataset and report titles include the notice: `"Download from x of y agent controllers failed."`

### Downloading results and report artifacts

To download test results, click _Download_ in the result set context menu. This produces a `.tar.gz` archive containing nested archives for all [_timers.csv_ files](/xlt/advanced/results/#collected-values).

In addition to full raw result archives, XTC provides direct access to key report artifacts:
- **AI Data (`ai-data.md`)**: a compact, LLM-optimized summary of test performance and error distributions.
- **Executive PDF (`load-report.pdf`)**: a printable A4 management summary report with KPIs, ratings, and core charts.

:::info[Role Required]
To use this feature, your account must at least have the role of a [reviewer](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

### Sharing results

:::info[Role Required]
To use this feature, your account must at least have the role of a [test manager](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

Sharing results in XTC resembles [sharing reports](/xtc/loadtesting/reports/#sharing-a-report). All project members with the [project role](/xtc/basics/projects/#user-roles-within-a-project) of **reviewer** or higher can access results. Project administrators can add users as reviewers to grant access.

To share results outside XTC, generate a **public sharing link** by clicking _Share_ in the result context menu. In the dialog, choose between the [default sharing settings](/xtc/loadtesting/load-project-configuration/#default-sharing-settings) and a custom expiration period for this link. The maximum lifetime of a share is 180 days.

Clicking _Create Share_ generates a public link, displayed as _Shared Link_ below the result entry. Anyone with the link can access the result data without logging in. Share links expire automatically and display no project information. You can revoke a link at any time by selecting _Unshare_ from the result context menu.

:::note
The public share link differs from the internal result URL. The internal result URL remains private and requires project authentication.
:::

To **change the expiration date** of a shared result, update the project [default sharing settings](/xtc/loadtesting/load-project-configuration/#default-sharing-settings) or select _Edit Share_ in the result menu. Updating the expiration alters the lifetime without changing the URL. To invalidate a shared link immediately, select _Unshare_.
To clear all custom shared links at once, use the cleanup option in the [project sharing settings](/xtc/loadtesting/load-project-configuration/#removing-all-custom-share-links).

### Creating a report from results

:::info[Role Required]
To use this feature, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

XTC allows generating [custom reports](/xtc/loadtesting/reports/#custom-reports) from any available result set. Click _Create Report_ in the result set context menu to open the report configuration dialog.

While creating a report from final results matches the behavior on the _Reports_ tab, this option allows **generating custom reports from intermediate test results** while a run progresses.

### Deleting results

:::info[Role Required]
To use this feature, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

To reclaim storage space, you can delete obsolete result sets by clicking _Delete_ in the result context menu and confirming the prompt.

If you delete a result set accidentally, XTC allows **restoring** it within 30 days. Click _Show Deleted Items_ in the three-dot table menu to view restorable items. Click _Undo Deletion_ in the item context menu to restore it. To return to active items, select _Hide Deleted Items_. Restored results require generating a new public share link if previously shared.
