## Default report

:::info[Role Required]
To view a test report, your account must at least have the role of a [reviewer](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

XTC automatically [creates a report](/xlt/manual/test-evaluation/) from the [results](/xlt/advanced/results/) collected at the end of a load test. Access the generated report under the _Reports_ section on the _Results_ tab, or download it as a compressed archive.

You can browse all reports directly within XTC or generate a link for [public sharing](#sharing-a-report).

:::note[Metadata Added by XTC]
The [Test Comment section](/xlt/manual/test-evaluation/#overview) of XLT load test reports is automatically enriched with data from XTC:

* The load test name and description.
* Metadata including organization and project short names, run numbers, and result identifiers.
* Optional report comments supplied when [creating a custom report](#custom-reports).

To omit metadata, uncheck _Include XTC Metadata_ in the _New Load Test Report_ dialog.
:::

## Intermediate reports

:::info[Role Required]
To use this feature, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

While a test is executing, you can generate [intermediate reports](/xlt/manual/test-evaluation/#intermediate-results) by clicking _Generate Intermediate Report_ at the top of the test content.

A prompt asks you to select which result artifacts to process. Intermediate reports cover test execution from the start up to the creation request, including ramp-up. Click _Accept_ to begin report generation.

![Prompt for creating an intermediate test report](/images/xtc/loadtest_intermediateReport.png)
*Prompt for creating an intermediate test report*

Only one intermediate report can generate at a time. The trigger button remains inactive while report generation is in progress.

Creating an intermediate report also produces an intermediate [test result](/xtc/loadtesting/results/), which you can use to build [custom intermediate reports](/xtc/loadtesting/results/#creating-a-report-from-results).

## Custom reports

:::info[Role Required]
To use this feature, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

After a load test completes, you can generate custom reports with specialized settings.

On the _Results_ tab, open the context menu for any result set and select [_Create Report_](/xtc/loadtesting/results/#creating-a-report-from-results), or click **NEW** at the top of the _Reports_ section. Clicking **NEW** uses the latest available result set, skipping pending, or failed results.

![Ways to create a custom test report](/images/xtc/loadtest_createReport.png)
*Ways to create a custom test report*

:::note
The **NEW** button activates only when valid result sets exist.
:::

A dialog prompts for report parameters: enter a label and description, and select a time range. By default, reports span the complete test duration, but you can configure custom start and end bounds like [reporting timeframes](/xlt/manual/report-options/#defining-a-reporting-timeframe) in XLT. The dialog displays the resulting effective timeframe:

![Basic settings for creating a new load test report: adjusting the time range.](/images/xtc/loadtest_report_timerange.png)
*Basic settings for creating a new load test report: adjusting the time range.*

Click **Show Advanced Settings** to access further configuration options:

* **Merge rules**: override project [merge rules](/xlt/advanced/merge-rules/). Paste complete rule sets to prevent unintended side effects.
* **Agent filters**: configure include and exclude patterns for [agents](/xlt/manual/report-options/#report-for-a-subset-of-agents).
* **Test scenario filters**: include or exclude specific [test cases](/xlt/manual/report-options/#excluding-test-scenarios).
* **Report generator properties**: apply custom [report configuration](/xlt/manual/report-configuration/) properties.
* **Exclude ramp-up (`noRampUp`)**: omit warm-up periods to inspect steady-state performance.
* **Executive PDF report**: compile an A4 printable PDF summary (`load-report.pdf`).
* **Time zone settings**: specify a reporting time zone such as "CET" or "EDT" (defaults to UTC).

Click _Accept_ to start report generation. The report appears in the reports list with a progress indicator. Once generation completes, click the report title to open and [inspect it](/xlt/manual/test-evaluation/#reading-a-test-report). If report generation fails, such as from invalid command-line properties, XTC marks the report as _failed_.

You can open reports while generation is in progress as soon as the HTML pages and overview charts become available. A distinct in-progress icon indicates partial availability:

![Topmost report upload in progress](/images/xtc/loadtest_report_inProgress.png)
*Topmost report upload in progress*

### Executive PDF report companion

Every load test report in XTC can generate a companion executive PDF report (`load-report.pdf`). Powered by Java (OpenHTMLtoPDF and Apache PDFBox), the PDF provides an A4 printable management summary containing:
- 6-segment executive rating score (`A+` to `F`), summary notes, and evaluation comments
- Centered vector charts for Concurrent Users, Requests/s, Request Runtimes, and Agent CPU load
- Aggregated SLA tables and Scorecard results

When compiled, download `load-report.pdf` directly from the report context menu or via the **PDF** link in the report navigation header.

### AI-assisted performance analysis

XTC integrates AI-assisted analysis capabilities designed to speed up post-test triage:
- **AI Data Export (`ai-data.md`)**: automatically included with every report. Download this file from the report context menu or access it inside the unpacked report. It provides a compact summary with explicit units, time-series metrics, and grouped error traces.
- **AI Analysis Reports**: use the AI Data artifact with your preferred AI coding assistant or internal LLM to assess SLAs, detect regressions against baseline runs, and isolate bottlenecks. For schema details and prompt recipes, see the [AI Data Report Guide](/xlt/manual/ai-data-report/).

:::

XTC records the configuration options used for each custom report. To inspect them, open the report context menu and select _Show settings_:

## Comparison reports

:::info[Role Required]
To create comparison reports, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

:::info[Role Required]
To read or download available comparison reports, your account must at least have the role of a [reviewer](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

Performance optimization is an iterative process. Code and infrastructure adjustments require verification through later load tests. Rather than inspecting two separate reports manually, use XTC [comparison reports](/xlt/manual/reports/#comparison-report) to highlight metric differences with color-coded diff views.

Because comparison reports compare two independent test runs, they live under the _**Comparison**_ section in the left navigation menu rather than under an individual load test.

The page includes the _Reports_ and _Comparison Reports_ tabs. The _Reports_ tab lists test reports flagged for comparison. To add a report to this list, select _Set Comparable_ from its context menu. To remove a report, deselect the option in the report list or delete it from the comparison tab.

![To make a report available for creating comparison reports, click _Set Comparable_ in the context menu in the load test reports list.](/images/xtc/loadtest_compare_setcomp.png)
*To make a report available for creating comparison reports, click _Set Comparable_ in the context menu in the load test reports list.*

To generate a comparison report, select two reports, and click **Compare**. The earlier test automatically serves as the baseline run. Select _Reverse Order_ in the dialog to invert the comparison roles. Enter a report name and optional description, then confirm. Once generated, the report appears on the _Comparison Reports_ tab.

![Select two reports from the list and click _Compare_ to create a new comparison report.](/images/xtc/loadtest_compare_compare.png)
*Select two reports from the list and click _Compare_ to create a new comparison report.*

![The _Create Comparison Report_ dialog.](/images/xtc/loadtest_compare_create.png)
*The _Create Comparison Report_ dialog.*

Comparison reports support the same actions as standard reports: renaming, [deleting](#deleting-a-report), [downloading](#downloading-reports), and [public sharing](#sharing-a-report).

## Trend reports

:::info[Role Required]
To create trend reports, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

:::info[Role Required]
To read or download available trend reports, your account must at least have the role of a [reviewer](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

Beyond individual and comparison reports, XTC supports **Trend Reports**. Trend reports track performance metrics across repeated test runs over time, helping teams identify regressions, and analyze longitudinal performance trends.

### Creating trend reports

To create a trend report in XTC:

1. Mark all relevant load test reports as *comparable* using the *Set Comparable* option in their context menu.
2. Navigate to **Comparison** in the left menu and open the **Reports** tab.
3. Select at least two source reports to include.
4. Click **Trend** on the toolbar to open the configuration dialog.
5. Enter a name and optional description, then submit.
6. Open the **Trend Reports** tab and select your report once generation completes.

### Report lifecycle and sharing

Trend reports support standard management workflows:

* **Pinning**: pin important trend reports to prevent automatic cleanup.
* **Sharing**: share trend reports through public links with external stakeholders.
* **Downloads**: download trend reports as standard compressed archives.
* **Lifecycle management**: XTC cleans up unpacked HTML files after 180 days (retaining downloadable archives) and keeps deleted reports in trash for 30 days.

## Sharing a report

:::info[Role Required]
To use this feature, your account must at least have the role of a [test manager](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

XTC simplifies sharing reports with team members and external stakeholders.

Users with the **reviewer** role can access all project reports. Project administrators can grant reviewer roles to more accounts as needed.

To share reports externally, generate a **sharing link**. Select _Share_ from the report context menu, then choose whether to use [project sharing defaults](/xtc/loadtesting/load-project-configuration/#default-sharing-settings) or configure a custom duration (up to 180 days).

![Creating a public sharing link](/images/xtc/loadtest_sharingLink_share.png)
*Creating a public sharing link*

![Creating a sharing link not using the default duration settings](/images/xtc/loadtest_sharingPopup_noDefault.png)
*Creating a sharing link not using the default duration settings*

Click _Create Share_ to generate the public link, displayed below the report as _Shared Link_. Anyone holding the link can view the report without logging in. Public links expire automatically, hide project details, and you can invalidate them manually via _Unshare_ in the context menu.

:::note
The sharing link differs from the internal report link. The internal report link remains private and requires authentication.
:::

You can update share lifetimes later. Change the [project sharing defaults](/xtc/loadtesting/load-project-configuration/#default-sharing-settings) to update all default shares, or click _Edit Share_ in the report context menu to set a new date. Changing the lifetime preserves the existing URL. To remove all custom shared links at once, use _delete existing custom share links_ in [project sharing settings](/xtc/loadtesting/load-project-configuration/#removing-all-custom-share-links).

![Editing the duration of a public sharing link or unsharing](/images/xtc/loadtest_sharingLink_editUnshare.png)
*Editing the duration of a public sharing link or unsharing*

## Downloading reports

:::info[Role Required]
To use this feature, your account must at least have the role of a [reviewer](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

To download a report, select _Download_ from the context menu. XTC provides a `.tar.gz` archive containing HTML pages, charts, and linked result browsers. The download option remains inactive until the backend finishes packaging and uploading the archive.

## Deleting a report

:::info[Role Required]
To use this feature, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

To remove a generated report and free storage space, select _Delete_ from its context menu and confirm the prompt.

If you delete a report accidentally, XTC allows you to restore it within 30 days. Click _Show Deleted Items_ in the reports table menu, locate the item, and select _Undo Deletion_. Restored reports require new public sharing links if shared earlier.

## Restoring an automatically retired report

XTC stores load test and comparison reports in two formats:

1. Unpacked directory containing HTML pages and chart images for browser viewing.
2. Compressed archive file used for downloads.

XTC **automatically retires** reports 180 days after creation to optimize storage. Retired reports remove unpacked browser files while preserving the compressed archive.

To view a retired report again, unpack the files from the archive. Verify that the project is active, open the report context menu, and select _Extract Archived Report_. Within a few minutes, the unpacked files become available for viewing for another 180 days.

:::info[Role Required]
To unarchive a retired report, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

## Errors on report creation

Report generation can fail if test suite properties contain invalid options. Click the _Error_ link next to a failed report to review the generator console log and diagnose root causes.
