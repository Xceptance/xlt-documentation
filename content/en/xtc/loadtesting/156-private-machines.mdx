Sometimes the system under test (SUT) is not accessible from the public internet—for example, when residing behind a corporate firewall or within an isolated network segment. In such environments, allowlisting every public cloud agent IP address in corporate firewalls is impractical.

A practical alternative is placing load generator machines within the same network segment as the SUT. Because external services cannot reach these machines directly, XTC classifies them as **private machines**. This model allows running load tests in network-isolated environments.

## How it works

Unlike public cloud or custom machines where XTC initiates inbound connections, private machines operate entirely within your internal network without exposing open inbound ports.

Instead, the private machine initiates all communication:
1. **Registration**: the XLT agent controller on the private machine registers with XTC via the REST API to signal availability.
2. **Tunneling**: the agent controller establishes a secure outbound tunnel to XTC through the **XLT Relay**. XTC dispatches load testing tasks through this tunnel.

Private machines must be online when the load test starts. You manage their operational lifecycle—either keeping them continuously active or automating provisioning via script workflows around test execution.

Apart from connectivity, private machines function identically to cloud machines. You can mix public cloud instances and private machines within the same test run.

## Prerequisites

To operate as a private machine, a host must meet the following criteria:

* **Connectivity**: outbound HTTPS connections to `xtc.xceptance.com` and `xtc-xlt-relay.xceptance.com` on port 443 must be open.
* **Java**: requires Java 21 or later installed.
* **XLT**: requires XLT 10.0.0-beta-2 or later installed.
* **Configuration**: requires configuring XLT for private machine mode.

## Setup steps

### Step 1. Create API client credentials
In your load testing project in XTC, create API client credentials with at least the `PRIVATEMACHINE_REGISTER` scope under *Configuration > Integrations > API Client Credentials*. Agent controllers on your private machines use these credentials to authenticate and register with XTC.

Save the generated client ID and secret. Note the short names of your XTC organization and load testing project.

### Step 2. Configure the XLT agent controller
Configure XLT for private machine mode on each private host by editing `<xlt>/config/agentcontroller.properties`. Configure the following properties:

| Property | Default | Description |
|---|---|---|
| `com.xceptance.xlt.agentcontroller.password` | `xceptance` | The password used to protect access to the agent controller. Must be the same for all machines. |
| `com.xceptance.xlt.agentcontroller.privateMachine.enabled` | `false` | Set to `true` to enable private machine mode. |
| `com.xceptance.xlt.agentcontroller.privateMachine.name` | _(auto-generated)_ | An optional human-readable name for this private machine as it appears in XTC. |
| `com.xceptance.xlt.agentcontroller.privateMachine.type` | `MEDIUM` | The capacity class of this machine. One of: `TINY`, `SMALL`, `MEDIUM`, `LARGE`. Make sure the specified type reflects the machine's actual hardware resources. |
| `com.xceptance.xlt.agentcontroller.privateMachine.xtc.clientId` | — | The client ID of the API credentials created in Step 1. |
| `com.xceptance.xlt.agentcontroller.privateMachine.xtc.clientSecret` | — | The client secret of the API credentials created in Step 1. |
| `com.xceptance.xlt.agentcontroller.privateMachine.xtc.org` | — | The short name of your XTC organization. |
| `com.xceptance.xlt.agentcontroller.privateMachine.xtc.project` | — | The short name of your XTC load testing project. |

### Step 3. Start the agent controller
Start the XLT agent controller on each private machine. The controller immediately registers with XTC. Verify that all machines appear on the **Private Machines** page of your project in the XTC UI.

## Using private machines in load tests

To use private machines in a load test:
1. Open the load test details page and navigate to the **Machines** tab.
2. Under the **Private Machines** section, specify the desired machine type, and enter the required count of machines. (Machines can remain offline during test configuration).
3. Enter the agent controller password from `agentcontroller.properties` in the **Common Machine Configuration** section.
4. Start the load test.

When the load test begins, XTC locates available private machines of the requested type and reserves them for the test duration. If insufficient machines are registered and online, the test fails to start.

Once the load test completes, XTC releases the reserved private machines, returning them to the available pool.
