:::info[Role Required]
To start, stop and abort load tests, your account must at least have the role of a [tester](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

## Starting a load test

:::note
Instead of manually starting your load tests, XTC can also [schedule tests](#scheduling-a-load-test) to start automatically at a planned time.
:::

To start the load test, click _Start_ in the context menu of the load test table, or click the _Start_ button on the load test details page:

![Start or schedule the configured load test via context menu.](/images/xtc/loadtest_start1.png)
*Start or schedule the configured load test via context menu.*

![Start or schedule the configured load test on the test page.](/images/xtc/loadtest_start2.png)
*Start or schedule the configured load test on the test page.*

A confirmation dialog prompts you to review and confirm the execution settings. Clicking _Start Load Test_ initiates the run:

1. **Fetches source code**: pulls the latest state of the test suite from the repository.
2. **Builds test suite**: compiles the project with Maven and populates the dependency cache.
3. **Provisions agents**: allocates and boots the required agent instances.
4. **Executes scenarios**: dispatches load profiles across agents and measures system metrics for the configured duration.

### Scheduling a load test

Instead of starting a load test immediately, you can schedule it for automatic execution. Ensure all test settings and agent configurations are accurate beforehand, as scheduling does not validate external dependencies until execution begins. You can cancel schedules or trigger immediate starts at any point.

To manage schedules, click _Schedule_ in the table context menu or on the test details page. Select your target date, time, and time zone (UTC by default). Convenient quick-select shortcuts (+1H, Tomorrow) simplify timing choices.

![Scheduling a load test.](/images/xtc/loadtest_schedule.png)
*Scheduling a load test.*

:::note
Once a load test is scheduled, you cannot edit test settings directly. To adjust parameters, remove the schedule, update the configuration, and reschedule the run.
:::

## Stopping a load test

XTC automatically completes load tests when their duration expires. The platform deprovisions cloud agents, collects test results, and generates the final performance report.

:::note
Only agent machines provisioned directly by XTC deprovision automatically. You must shut down any custom agent machines manually.
:::

If XTC encounters an issue releasing an agent machine, it flags the _Terminate Agents_ step on the test's _Status_ tab.

### Aborting a load test

You can abort a running load test early if unexpected conditions arise—such as incorrect test suite parameters, high error spikes on the [scenario overview](/xtc/loadtesting/monitor-lt/#scenario-status), or backend outages. To stop execution, click _Abort Load Test_ in the top-right corner.

![Abort the load test.](/images/xtc/loadtest_abort_click.png)
*Abort the load test.*

A modal prompts you to confirm the cancellation. If test scenarios already produced data, you can choose which artifacts to collect and decide whether to generate a partial report. Skipping unneeded artifacts, such as full result browsers, accelerates final data collection.

XTC immediately stops running scenarios and deprovisions all active agents.

![Popup after clicking Abort Load Test in a test run.](/images/xtc/loadtest_abort.png)
*Popup after clicking Abort Load Test in a test run.*

While the abort procedure is in progress, the _Abort Load Test_ button turns off for all users until cleanup completes.

:::note
Only agent machines provisioned by XTC deprovision automatically after aborting. You must shut down custom agent machines manually.
:::
