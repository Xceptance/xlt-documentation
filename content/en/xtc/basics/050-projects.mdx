Organizations are containers for projects, which in turn are the containers for any kind of test run in XTC.

## XTC project types

Projects belong to one of two categories: [monitoring projects](/xtc/monitoring) or [load testing projects](/xtc/loadtesting).

**Load testing projects** execute configurable performance tests, such as tests that ramp up user load over time. XTC stores execution results and generates performance reports, providing centralized test management, and analysis.

**Monitoring projects** execute test scenarios periodically to observe app reliability and performance over time, including functional monitoring of production systems. Define validation criteria such as runtime limits and error thresholds. Criterion violations trigger automated notifications according to configured rules.

The project tile displays the project type:

![A monitoring project on the dashboard of the _Xceptance_ organization.](/images/xtc/organizations_monitoringProject.png)
*A monitoring project on the dashboard of the _Xceptance_ organization.*

The sidebar menu adjusts depending on whether you open a [load test project](/xtc/loadtesting) or a [monitoring project](/xtc/monitoring):

![The menu of a monitoring project (left) and a load testing project (right).](/images/xtc/project_menus.png)
*The menu of a monitoring project (left) and a load testing project (right).*

Each project maintains its own [members](#adding-and-removing-project-members) and [configuration](/xtc/basics/project-configuration/) independently of other projects.

## Creating a new project

:::info[Role Required]
To create new projects, your account must have the role of an [organization administrator](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

To create a project within an organization, navigate to the organization and select _Projects_ from the left menu.

The page displays all existing projects within the organization:

![A list of projects in an organization, as seen by the organization administrator.](/images/xtc/ui_projectsInOrg.png)
*A list of projects in an organization, as seen by the organization administrator.*

Click `+` in the top right to create either a [Monitoring Project](/xtc/monitoring) or a [Load Testing Project](/xtc/loadtesting). You cannot change the project type after creation.

![Adding a new project](/images/xtc/ui_newProject.png)
*Adding a new project*

When creating a project, enter a display name and a short name. The short name must be unique within the organization. It must start with a lowercase letter, contain at most 39 lowercase letters, digits, and hyphens, and cannot end with a hyphen.

You can edit project details later from the project context menu by selecting _Edit_.

To duplicate an existing project, select _Duplicate_ in its context menu. This copies the configuration to a new project.

When duplicating a project, assign a new short name unique to the organization. The new project copies the full source configuration. By default, duplicated projects start in the _Locked_ state; switch the state to _Active_ using _Edit_ in the context menu.

## User roles within a project

The user who creates a project becomes its first administrator and can add project members. When adding users who are not yet organization members, XTC automatically adds them as organization guests.

Project members hold one of five roles:

* **Guest**: views only the project dashboard.
* **Reviewer**: views test details, reports, scenario executions, and history.
* **Tester**: creates, configures, and executes load tests or views monitoring logs.
* **Test manager**: edits project configurations for load testing and monitoring projects.
* **Project administrator**: manages all project settings and project members.

Permissions increase hierarchically. For example, a tester retains all reviewer permissions.

When viewing a project, your assigned role appears in the footer on the bottom right:

![Footer displaying the user's role in the project.](/images/xtc/ui_projectRole.png)
*Footer displaying the user's role in the project.*

## Adding and removing project members

:::info[Role Required]
To use this feature, your account must have the role of a [project administrator](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

To **add members to a project**, navigate to the project and select _Members_ from the left menu. Click `+` in the top right, enter the user email address, and select a role.

By default, you can assign users who already belong to the [organization](/xtc/basics/organizations/#adding-members-to-an-organization). You can also [invite external users](#inviting-users-to-join-a-project).

To add users in bulk, paste a list of email addresses separated by commas, newlines, or spaces. All listed users receive the chosen role.

To **update a member role**, open the context menu next to the user name on the _Members_ page and select _Edit Role_.

To **remove a member**, open the context menu next to the user name, select _Remove_, and confirm the prompt.

:::note
Removing members from a project does not delete them from the organization. To revoke organization access, remove them from the organization directory explicitly.
:::

### Adding user groups to a project

:::info[Role Required]
To use this feature, your account must have the role of a [project administrator](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

Instead of assigning individual users, you can add an existing organization **[user group](/xtc/basics/organizations/#user-groups)** to a project.

Navigate to the project _Members_ page, select the _User Groups_ tab, and add each group with the intended project role. Adding users to the group later grants them project membership automatically.

### Inviting users to join a project

:::info[Role Required]
To use this feature, your account must have the role of a [project administrator](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

Project administrators can invite external users if the organization enables [user invitations](/xtc/basics/organizations/#organization-configuration). Follow the steps to [add project members](#adding-and-removing-project-members), and activate the _Invite Users_ toggle.

Invited users receive an email with a registration link. Upon registration, XTC adds them to the organization as guests and grants project access.

Invitations remain valid for 30 days. Administrators can resend pending invitations from the _Members_ page. Unclaimed invitations are automatically deleted after 90 days.

### Adding administrators to a project

:::info[Role Required]
To use this feature, your account must have the role of an [organization administrator](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

If a project lacks an active administrator, an organization administrator can assign new administrators or promote existing members.

From the organization _Projects_ page, select _Add Project Admins_ in the project context menu. Enter the email addresses of the users to assign as project administrators.

## Project states

Projects use three operational states that control access and visibility:

* **Active**: the project is visible to all members, who can interact according to their permissions.
* **Inactive**: the project remains visible in read-only mode. Users cannot create or edit resources. In monitoring projects, scenario execution pauses. In load testing projects, users cannot start new tests. Set a project to inactive when testing concludes but historical results remain relevant.
* **Archived**: XTC hides the project from dashboards and the header selector. XTC unshares shared reports and results, invalidating public links. XTC preserves all project data. Archive projects that are complete and no longer need active review. XTC notifies members via email and Slack when archiving a project.

Authorized roles can update project states:

* A [project administrator](#user-roles-within-a-project) can toggle the state between active and inactive under _Configuration > General > Project State_.
* An [organization administrator](/xtc/basics/organizations/#user-roles-within-an-organization) can set all three states from the organization _Projects_ page using _Change State_ in the context menu.

You can reactivate an inactive or archived project at any time.

:::note
Project states do not alter the base fee for a project. Standard fees apply regardless of state.
:::

## Deleting a project

:::info[Role Required]
To delete a project, your account must have the role of an [organization administrator](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

To delete a project, open the organization _Projects_ overview, open the context menu for the project, and select _Delete_. Enter the project name to confirm deletion.

You can delete only [active or inactive](#project-states) projects. You cannot delete [archived](#project-states) projects directly.

If you delete a project accidentally, XTC allows you to restore it within 30 days. Select _Show Deleted Items_ from the project table menu, find the project, and click _Undo Deletion_.

## Project documentation

Every XTC project includes a documentation page in the side navigation. Use this page to share testing objectives, success criteria, schedules, and contact details with team members. The page supports standard Markdown formatting.

:::info[Role Required]
To view the documentation page, your account must at least have the role of a [reviewer](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

:::info[Role Required]
To edit the documentation, your account must at least have the role of a [test manager](/xtc/basics/projects/#user-roles-within-a-project) within the project.
:::

:::warning
Because all project members can view the documentation page, do not store sensitive information such as credentials on it.
:::
