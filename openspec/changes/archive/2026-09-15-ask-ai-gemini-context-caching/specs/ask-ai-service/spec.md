## Purpose

Provides a serverless proxy and Vertex AI Gemini Context Caching pipeline to answer reader questions against the complete Xceptance documentation corpus with low latency and zero static server maintenance.

## ADDED Requirements

### Requirement: Serverless Streaming API Endpoint
The Ask AI service SHALL provide an HTTP endpoint that validates requests, enforces origin restrictions, and streams answers generated by Google Gemini directly back to the client as plain UTF-8 text chunks.

#### Scenario: CORS preflight handling for allowed origins
- **WHEN** a browser client issues an HTTP `OPTIONS` preflight request from an allowed origin specified in configuration
- **THEN** the service responds with HTTP status 204 and headers permitting `POST` requests and the `Content-Type` header.

#### Scenario: CORS rejection for disallowed origins
- **WHEN** a browser client sends a request with an `Origin` header that does not match any configured allowed origin
- **THEN** the service does not return `Access-Control-Allow-Origin` for that origin, preventing unauthorized cross-origin browser access.

#### Scenario: Streaming question answering with conversation history
- **WHEN** a client issues an HTTP `POST` request with a valid multi-turn conversation history (user and assistant messages)
- **THEN** the service transforms the history into model format, queries Gemini with the active context cache, and streams tokens to the client with `Content-Type: text/plain; charset=utf-8` and HTTP status 200.

#### Scenario: Question answering with current page context injection
- **WHEN** a client issues an HTTP `POST` request containing a valid `page.path` property
- **THEN** the service appends the page context note to the user prompt so Gemini prioritizes the chapter the reader is actively viewing.

#### Scenario: Question answering without page context
- **WHEN** a client issues an HTTP `POST` request where `page` is omitted or null
- **THEN** the service answers the question against the global documentation cache without failing.

#### Scenario: Rejection of non-POST HTTP methods
- **WHEN** a client sends an HTTP `GET`, `PUT`, or `DELETE` request
- **THEN** the service responds with HTTP status 405 Method Not Allowed and sets the `Allow` header to `POST, OPTIONS`.

#### Scenario: Malformed or missing payload rejection
- **WHEN** a client sends a request without a valid array of messages, with empty content, or with invalid message roles
- **THEN** the service responds with HTTP status 400 Bad Request and an explanatory error message without querying Gemini.

#### Scenario: Upstream model error handling
- **WHEN** the upstream Gemini API call fails or encounters a network error
- **THEN** the service logs the error and gracefully streams an error notice to the client rather than hanging or crashing the process.

### Requirement: Gemini Context Caching Pipeline
The service SHALL provide an automated cache management script that indexes the full compiled documentation corpus (`dist/llms-full.txt`) into Google Vertex AI Context Caching using the configured model version with an extended time-to-live.

#### Scenario: Documentation corpus cache creation
- **WHEN** the cache refresh script is executed with `dist/llms-full.txt` present
- **THEN** the script creates a Vertex AI CachedContent resource containing the complete documentation text, sets a 30-day time-to-live, and outputs the unique cache identifier.

#### Scenario: Dynamic model synchronization
- **WHEN** the model variable `GEMINI_MODEL` is configured (defaulting to `gemini-2.5-flash` or the latest caching-capable model)
- **THEN** both the cache refresh script and the streaming Cloud Function evaluate against that exact model version.

### Requirement: Environment Configuration and Project Portability
The service SHALL provide distinct environment configuration profiles for development and production to prevent test activities from polluting production resources and enable seamless migration.

#### Scenario: Environment profile selection
- **WHEN** the deployment script is invoked with an environment argument (`dev` or `prod`)
- **THEN** the script loads the corresponding environment profile (`.env.development` or `.env.production`) and configures the target project, region, function name, and CORS origins accordingly.

#### Scenario: Explicit project identifier enforcement
- **WHEN** the deployment or cache script is executed without `GCP_PROJECT_ID` explicitly set in the environment or loaded configuration profile
- **THEN** the script terminates immediately with a non-zero exit code and an explanatory error message, preventing accidental deployment or cache corruption from ambient CLI defaults.

### Requirement: Secret and Project Identifier Git Hygiene
The repository SHALL exclude all actual environment files, Google Cloud project identifiers, and credentials from Git tracking, providing only generic example templates in version control.

#### Scenario: Git exclusion of environment configurations
- **WHEN** git status is inspected with local `.env`, `.env.development`, or `.env.production` present
- **THEN** all `.env*` files except `.env.example` are ignored by git and prevented from being committed.

#### Scenario: Template availability without sensitive defaults
- **WHEN** a developer inspects `.env.example`
- **THEN** it contains clear documentation and placeholder values (e.g. `your-gcp-project-id`) without exposing any real personal or company project identifiers.
